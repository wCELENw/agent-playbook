# Студия — как команда агентов ведёт проект

Процесс для проекта, где координатор (Producer) раздаёт работу воркерам-ролям. Основа —
[studioigor/gamestudio](https://github.com/studioigor/gamestudio) (MIT), обкатано на десятках проектов.
Каждое правило здесь стоило реального отказа.

## 1. Правила владельца

1. **Один агент — одна роль — одна задача.** Задача воркера — пачка карточек **одной зоны для одной
   роли**. Роли и зоны в одной задаче не смешиваются.
2. **Каждый агент — в отдельном воркере** (Orca). Координатор воркером не является: он
   декомпозирует, пишет спеки, читает дифф, мержит.
3. **Своя модель и effort у каждой роли** — во frontmatter `.claude/agents/<роль>.md`.
4. **caveman и ponytail, уровень full, у всех агентов.** Документы, CHANGELOG, карточки и
   коммиты — обычной прозой.
5. **Каждая итерация закрывается ролью `doc-keeper`**: STATUS, доки, `CHANGELOG.md`.
6. **Крупный блок начинается с плана** (роль `architect`); код — после утверждённого плана.
7. **Лишнего не заводим:** роли и навыки — только нужные сейчас; новая роль — решением владельца.

## 2. Роли

| Роль | Владеет | Зона |
|---|---|---|
| `architect` | план этапа, ADR, разрез на зоны и карточки | `docs/plans/`, `docs/decisions/` |
| `doc-keeper` | STATUS, перенос решений в доки, `CHANGELOG.md` | `docs/STATUS.md`, `CHANGELOG.md` |
| `qa-tester` | приёмка по сценариям, карточки `bug-` | `docs/qa/`, `tasks/open/bug-*` |
| _<роли проекта>_ | _код/контент своей зоны_ | _пути_ |

Ревьюера и интегратора нет: дифф читает и мержит Producer.

## 3. Цикл крупного блока

1. **План.** `architect` пишет `docs/plans/stage-N.md`: цель, зоны, карточки с майками, риски, ADR.
2. **Утверждение.** Producer показывает план владельцу; развилки — вопросами по одной
   (рекомендуемый вариант первым).
3. **Очередь.** Карточки — в `tasks/open/` (§5).
4. **Пачки.** Одна роль и зона, 15–20 весов, не больше одной XL и двух L.
5. **Приёмка.** Producer читает дифф, сводит в интеграционную ветку, гоняет ворота там, мержит.
6. **QA.** Один проход на собранное; баги — пачками по зонам.
7. **Документация.** `doc-keeper` закрывает итерацию.

Малая задача (одна зона, без новых решений) идёт сразу с шага 3.

## 4. Проверка по риску

- **Ревью диффа обязательно**, если правка трогает общего владельца факта (состояние, деньги,
  сохранение, протокол).
- Раскладка, цвет, текст — без глубокого чтения; ловит приёмка.
- **Один владелец у каждого факта.** Правка, заводящая второго владельца, отклоняется.
- Тест — только на критический сценарий или найденный баг; обязан краснеть без починки.
- Опровергающая приёмка — только по триггерам: общий владелец факта, починка бага, закрытие этапа
  (скилл `agent-delegation-and-verification`, п.5).

## 5. Очередь — `tasks/`

- Работа берётся только из `tasks/open/`. Приставки: `NN-` (выпуск), `bug-`, `debt-`, `idea-`, `later-`.
- Карточка: первая строка — роль и зона, вторая — майка. Разделы: DoD, критерии приёмки,
  критерии тестирования; хотя бы один критерий — наблюдаемое поведение.
- Майки: XS 1 · S 2 · M 3 · L 5 · XL 8. Часы не оцениваем.
- Закрыл — удали файл, добавь строку в `tasks/DONE.md`.

## 6. Деньги

- Мера эффективности — запусков воркеров на закрытую карточку. Цель — не больше двух.
- Экономия — из меньшего числа стартов, а не из слабой модели.
- Незаменимый провайдер тратится последним (растр — только Codex).
- Спека короткая: цель, карточки, границы-запреты, наблюдаемый результат с числом «до», прямой
  вопрос для первой строки отчёта, указатели `файл:строка`. Механизм выбирает исполнитель.
