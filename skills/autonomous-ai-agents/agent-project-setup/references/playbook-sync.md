# Синхронизация публичного playbook с машиной

Playbook владельца (`github.com/wCELENw/agent-playbook`, клон — `C:\Proj\agent-playbook`, ветка `main`)
и живая конфигурация (`~/.agents/GLOBAL_RULES.md`, `$HERMES_HOME/skills/`) расходятся в обе стороны:
новые правила рождаются локально, новые навыки — в репо. Синхронизировать — значит свести ОБА направления.
Направление репо → машина делает ежедневный `scripts/sync_playbook.py` (задача `agent-playbook-sync`);
разбор его строк CONFLICT/LOCAL и перенос машинных уроков в репо — скилл `multi-machine-agent-sync`.

## Порядок

1. **Инвентаризация полным множеством, а не по списку расхождений.** Цикл по `skills/*/*/` репо:
   для каждого файла навыка — есть ли он локально (`$HERMES_HOME/skills/<кат>/<имя>/<файл>`) и
   совпадает ли (`cmp` после `tr -d '\r'`). Отдельно — обратный проход: файлы локальной копии, которых
   нет в репо (`references/*`, `scripts/*`). Сравнение только «отличающихся» файлов пропускает
   неустановленные навыки целиком — их может оказаться больше половины.
2. **GLOBAL_RULES:** живой файл новее по §1–10 (маршрутизация), репо может хранить разделы, которых
   локально нет. Слить в обе стороны; в репо — плейсхолдеры (`<OWNER_CHAT_ID>`, `<tailnet>`) вместо
   реальных значений. Писать В живой файл, симлинки харнессов (`SOUL.md`, `~/.claude/CLAUDE.md`,
   `~/.codex/AGENTS.md`) не ломать — проверить `ls -l` после.
3. **Публичная версия без частного:** названия личных проектов и рабочих контекстов, chat id, хосты
   tailnet — обобщить в репо; в локальной копии частные примеры можно оставить. Проверка перед
   push — `scripts/check-public.sh` (нужен deny-list `~/.agents/public-scrub.txt`); без него —
   `git grep -n -i` по списку частных терминов, результат пуст.
4. **Производные артефакты** (README EN/RU, `docs/how-it-works*.{html,json,png}`) — сверить с новыми
   правилами той же волной; PNG перегенерировать отдельной задачей и сказать владельцу, если отложено.
   Перед регенерацией схем — убедиться, что всё упомянутое в них установлено на машине.
5. **Приёмка:** `git diff --stat` — только ожидаемые файлы; `git diff --check`; json валиден; концы
   строк сохранены (`file` → CRLF где был); итоговый полный проход п.1 — расходятся только намеренно
   частные строки. Коммит явными путями, push, `git status -sb` → `main...origin/main` без ahead.

Все записи (копирование навыков, правки репо) — Orca-воркерами по §9, даже «механическое» копирование:
координатор только сверяет и коммитит.
