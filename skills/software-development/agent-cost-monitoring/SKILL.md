# Учёт стоимости работы агента (оплата по токенам)

## When to Use

- пользователь платит за токены (API-провайдер, а не подписка) и просит «сколько это будет стоить»;
- нужен отчёт «факт против оценки» по этапу работы или прайс фичи целиком;
- надо сверить ставки провайдера для расчёта, а не брать их на память.

**Don't use for:** подписочные тарифы и фиксированные пакеты — там цена блока не зависит от токенов.

## Процедура

1. **Найти источник счётчиков.** Для Hermes — `~/AppData/Local/hermes/state.db`
   (`session_model_usage`, `sessions`); схема и готовые запросы — `references/hermes-usage-store.md`.
   Если источник накопительный — снимать точку **до** и **после** этапа и отчитываться дельтой.
2. **Взять ставки с первоисточника** — страницы конкретной модели у провайдера, сверив имя модели
   с конфигом (`config.yaml` → `model.default`). Три категории токенов считаются раздельно:
   некэшированный вход, выход, чтение из кэша. Формула:
   `cost = in/1e6*rate_in + out/1e6*rate_out + cache/1e6*rate_cache`.
3. **Калибровка вместо гадания.** Измерить среднее на вызов API в этом же проекте (типовой профиль:
   ~7–8k свежего входа, ~140k кэша, ~0.7k выхода на вызов) — и переносить его на новый блок:
   `цена блока ≈ вызовы × цена_вызова`. Планировать по вызовам API, а не по числу реплик.
4. **Учесть делегирование.** Субагенты/агенты поднимают свой контекст и перечитывают файлы —
   надбавка ~30 % к соло-оценке. В Hermes дети пишутся **отдельными сессиями** с
   `sessions.parent_session_id` = сессия координатора — выбирать их запросом по этому полю и
   приплюсовывать, иначе расход этапа занижен на всю работу агентов. С указателями `файл:строка`
   в задании расход блока падает вдвое-втрое против оценки (замер: блок кода — 16 вызовов / 7.5 ₽).
   Надбавка за делегирование зависит от **вида правки**, а не от числа вызовов: строка в реестре
   данных — 16 вызовов / 7.5 ₽, а правка внутри интерактивного экрана с циклом перерисовки, новыми
   тестами и неожиданной починкой заглушек — 76 вызовов / 43.7 ₽, то есть шестикратный перерасход
   против сметы. Такие блоки оценивать с множителем 2–3 и назвать владельцу диапазон; в цену блока
   отдельными строками входят приёмка (5–6 ₽) и координация (8–27 ₽ — перечитывание диффа, прогоны
   гейтов, деплой), они не «бесплатные».
5. **Отчёт блока:** вызовы, вход/выход/кэш, рубли — рядом с прежней оценкой, плюс накопительный итог
   по фиче. Отчёт без дельты не отчёт.
6. **Гейт по согласию.** На платном счёте перед каждым следующим этапом назвать его цену и получить
   явный акцепт; без акцепта не начинать.

## Pitfalls

- **Считай делегирование по детям, не по себе:** расход субагентов виден только в их сессиях, поэтому
  отчёт, собранный из счётчика координатора, занижает этап — это ошибка самой распространённая.
- **Цену за нагрузку нельзя выводить из числа реплик** — считать только по вызовам API.
- **Оценку делать по виду правки:** одна строка в таблице данных и вставка внутрь цикла
  интерактивного экрана отличаются в разы, хотя в задании выглядят одинаково. Если блок трогает UI,
  заглушки тестов или требует новых проверок — говорить это в оценке прямо.

- **Цену брать со страницы самой модели, а не из FAQ/сравнений/каталога:** FAQ и compare-страницы
  устаревают, а строка в каталоге может показывать как «ввод» цену чтения из кэша (разница в разы).
  Проверять: имя модели == `model.default` в конфиге, затем цена на её странице.
- **`input_tokens` в счётчиках — обычно только НЕкэшированный вход**; кэш — отдельное поле. Умножать
  всё на входную ставку — завысить счёт в разы.
- **Длинный диалог дорожает не длиной, а перечитыванием контекста:** основная статья — чтение из кэша
  и свежий вход на каждом вызове. Дешевле делать меньше вызовов и не перечитывать большие файлы.
- **Самая дорогая ошибка — найденная на стороне пользователя:** правка после ручного прогона стоит
  как десятки вызовов. Проверять всё, что можно, автотестами и харнессом ДО передачи пользователю.
- **Найденный факт — один раз:** переиспользуемые факты (API, ограничения, найденные пути) фиксировать
  в файле проекта, иначе следующая итерация платит за повторное чтение.
- **Считать и фоновые вызовы плагинов, а не только модели задачи:** хуки Claude Code (claude-mem)
  зовут свою модель (Haiku) на каждое событие сессии; за 5 дней на одной машине это ~4300 вызовов
  (~$45), 60 % — запись кэша с TTL 1 час. Источник — `~/.claude-mem/claude-mem.db` (`sdk_sessions`,
  `observed_model`). Для Orca-воркеров отключать: пункт 14 `docs/startup-settings.md` playbook.
- **Оценка не должна быть оптимистичной:** на вопрос «сколько будет стоить» давать диапазон
  (экономно/вероятно/с отладкой) и указывать, что меняет цену (число итераций после прогона
  пользователем, переделки, объём делегирования).
