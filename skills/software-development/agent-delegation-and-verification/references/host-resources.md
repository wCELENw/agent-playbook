# Ресурсы хоста при параллельных воркерах

## Память координирующего хоста (minipc)

- 16 ГБ физически, из них 4 ГБ забирает UMA iGPU (Radeon 780M) — Windows видит 11,8 ГБ. Каждый
  Claude-воркер ~0,3 ГБ, Orca ~0,6, WSL/Docker ~2,4 + контейнер симуляции 0,5–1 ГБ.
- Держать ≤ 3 воркеров одновременно. При нехватке RAM Claude Code убивает фоновые команды
  воркера; лёгкое ожидание (ssh-опрос) можно перезапустить, тяжёлое — на powerpc-1.
- Диагностика одной командой: `Win32_OperatingSystem.FreePhysicalMemory`, `Get-Process | group Name`
  по WorkingSet, `docker stats --no-stream`, `Win32_PhysicalMemory` (число планок, канальность).
  Смотреть и `PrivateMemorySize64` (а не только WorkingSet) и commit (`TotalVirtualMemorySize −
  FreeVirtualMemory`): WorkingSet скрывает вытесненное в подкачку. По python-процессам — с командной
  строкой (`Win32_Process.CommandLine`), иначе не понять, чей он. Сложные PowerShell-команды (`-f`,
  регулярки, `$_`) запускать из `execute_code` через `subprocess.run(['powershell','-NoProfile',
  '-Command', ps], encoding='cp866')`, а не из bash: экранирование bash ломает `$`/`\` и `{0}`.
- После уборки Docker остаются постоянные потребители: процесс Hermes gateway (растёт с длиной
  сессии до 1,5–2 ГБ), открытый Hermes TUI, `chroma-mcp` плагина `claude-mem`, Orca. Называть
  их владельцу с цифрами и не закрывать самому. `/new` в Telegram историю не теряет (все сессии
  в `state.db`, ищутся поиском); рост контекста сдерживает более раннее сжатие
  (`hermes config set compression.threshold 0.25`, читается на каждом ходу), но уже занятую
  память процесса освобождает только его перезапуск.
- Рычаги без покупок: уменьшить UMA Frame Buffer в BIOS (только владелец руками; на машине есть
  игровой режим — спрашивать размер), `.wslconfig`, перенос Docker-прогонов на powerpc-1, лимит
  воркеров. Боты других проектов в Docker — живые сервисы владельца, не трогать. Переходников
  DDR4↔DDR5 SODIMM не существует (разные напряжение, PMIC на модуле, распиновка).

## Docker на несколько воркеров

- В спеку: свой `COMPOSE_PROJECT_NAME`, «свободно ≥ 1,5 ГБ перед запуском», один контейнер за раз,
  `docker compose -p <name> down` после.

## Перезапуск WSL для `.wslconfig`

- `.wslconfig`: `[wsl2] memory=6GB` + `[experimental] autoMemoryReclaim=gradual` (без него vmmem держит
  память). Применяется только `wsl --shutdown` — он останавливает ВСЕ контейнеры, включая
  боты других проектов. Нужно согласие владельца.
- Не делать сразу: оборвёт Docker-проверки воркеров. Фоновый скрипт (`notify=true`): ждать,
  пока `docker ps` без контейнеров проекта (префикс проекта) два опроса подряд с шагом 30 с (воркер
  может запустить следующий контейнер между шагами) → `wsl --shutdown` → запуск
  `C:\Program Files\Docker\Docker\Docker Desktop.exe` → ждать `docker info` → сравнить список
  контейнеров до/после. Перед запуском проверить `RestartPolicy` чужих контейнеров
  (`unless-stopped` поднимается сам).
- Порядок с воркерами: до старта скрипта разослать «после текущего контейнера новый Docker не
  запускай, жди сигнала»; по итогу скрипта — «Docker свободен» каждому (`terminal send`). Воркеру,
  чью проверку убила нехватка RAM, отвечать «жди моего сигнала», а не «жди RAM ≥ X»: он
  иначе стартует перед самым `wsl --shutdown`.
- Потолок `memory=` ограничивает только WSL; свободная RAM Windows после перезапуска может
  не вырасти — сразу смотреть остальных потребителей (см. выше), не обещать прирост заранее.

## Деление полных прогонов между ПК

- Предпочтение владельца: если онлайн powerpc-1, полный прогон делить ~70 % powerpc-1 / ~30 % minipc
  по спекам и числу боёв, чтобы оба закончили одновременно. Короткие быстрые проверки (минуты)
  не делить — пересылка кода съедает выигрыш.
- powerpc-1: репо обновляется bundle-файлом (у него нет доступа к GitHub по ssh), фон — через WMI-обёртку
  проекта (переживает закрытие ssh). Не ставить CPU-прогон поверх идущего GPU-прогона 3D и
  не превышать 12 потоков суммарно: машина перегревается.
- Bundle для `scp` создавать в каталоге репо (или по нативному Windows-пути), не через `mktemp`:
  MSYS-путь `/tmp/...` нативный `git`/`scp` не находит (`scp: stat local ... No such file`).
- Обёртку «запустить команду проекта на powerpc-1» сначала прогнать пробной командой и только
  потом вписывать в `CLAUDE.md` и спеки воркеров — непроверенный путь воркеры размножат.
